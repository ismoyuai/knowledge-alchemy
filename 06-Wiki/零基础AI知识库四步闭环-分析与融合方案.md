# 零基础 AI 知识库四步闭环 · 分析与融合方案

> 素材：姜胡说抖音视频《零基础搭AI知识库，四步闭环越用越聪明》正文（`03-Resources/视频文案提取.md`）+ 配套模板（根目录 `User.md`）
> 本文是对它的分析和融合方案，**不是摘要**。

---

## 0. 一页结论

**视频给的是一套「用 AI 学 AI」的操作方式，不是一套目录结构。**

你的新库已经有骨架（三环迭代 + PARA + 4 Skills）。两者**不是竞争关系，是配对的**：

| | 提供什么 |
|---|---|
| 视频 | **操作方式** —— 怎么跟 AI 说、怎么喂内容、怎么复盘 |
| 你的新库 | **容器** —— 东西放哪、怎么流转 |

**所以不该"合并两套结构"（那是拿两套目录打架），而是"给容器装上操作方式"。**

**对照下来，新库缺三块：**

| # | 缺什么 | 严重度 | 本文方案 |
|---|---|---|---|
| 1 | **`User.md` 身份档案** | 🔴 高 | 放到根目录，与 `AGENTS.md` 并列 |
| 2 | **「现在用 / 未来用」分流闸门** | 🟡 中 | 写成 `07-原子库/` 的入口规则 |
| 3 | **每日复盘的落点** | 🔴 高 | ⚠️ **与你刚删掉 `06-Journal` 直接冲突**，见第 5 节 |

**这两份文件现在放在 `00-灵感库/`，但都不符合入盒四规则。**

| 文件 | 实际性质 | 该去哪 |

## 2. 视频方法拆解

### 2.1 四步闭环

| 步 | 动作 | 原话要点 | 底层原理 |
|---|---|---|---|
| **一** | **工具准备** | 下 WorkBuddy + QoderWork，免部署、每天送积分 | **降低启动摩擦** —— 不配环境，先用起来 |
| **二** | **建档案** | 告诉 AI 你是谁/干嘛/优缺点/目标/卡点，让它记住你 | **让 AI 知道"你是谁"，建议才有针对性** |
| **三** | **喂内容** | 看到好内容**不要收藏**，直接给 AI；问"根据我的情况，这知识我怎么用" | **输入必须被加工才叫学习** |
| **四** | **每天复盘** | 告诉 AI 用了什么、结果如何，让它复盘并给改进 | **闭环 —— 不复盘就没有迭代** |

### 2.2 埋在每个步骤里的关键判断

**第一步的三条禁令**（比"下什么工具"更重要）：
1. 不要一上来纠结装 Claude Code / Codex / Hermes
2. 不需要配环境
3. "刚开始够用就好了"
> 原话："击倒对方最好的方法不是猴拳，也不是泰拳，就是手枪。" —— 意思是**能用的最简工具 > 学不会的强工具**。

**第二步的一句话点破了为什么要建档案**：
> "把它当成一个几十万的咨询顾问，把你的情况跟它说，让它记住你。"

**第三步最有价值的不是"喂"，是那个分流动作**：
> "是现在马上可以用，还是未来可以用？如果是未来可以用，你把它整理成知识块的方式，存放在一个目录里边，以后有用的时候拿出来。如果是现在用，马上告诉我一二三怎么用。"

**这是一个天然的二分闸门**：

```
喂进来的内容
   ├── 现在能用  → 立刻输出 1-2-3 行动项 → 照做
   └── 未来能用  → 压成「知识块」存起来 → 待取用
```

**第四步的价值在于它把"输入"变成了"回路"**：
> "一天两天三天四天五天，你就完全和别人不一样了。"

### 2.3 全片的立场

> "一定要先用出来。我发现我们很多人学东西学傻了，一定要先学会了再去用。打球的方法是什么？**是先上场**。不是在网上看十年教学视频，看了十年还不会打球。"

**先上场，一边学一边用，甚至不需要懂。**

### 3.1 一个重要的结构发现

**视频的四步，和你新库的三环，是同一个东西的两种说法：**

```
视频：  工具准备 ─┐
               ├─ 基础设施  ┐
        建档案  ─┘           │
                           ├─→  你的新库 = 三环
        喂内容  ─────────────┤    第一环 入口触发
                            │    第二环 验证加工
        每天复盘 ────────────┘    第三环 认知演进 + 回灌
```

**结论：新库的三环 = 视频的第三步 + 第四步。而视频的第二步（建档案）是这套骨架里唯一没有对应物的东西。**

## 4. 三个缺口与融合方案

### 4.1 缺口一：`User.md` 身份档案

**它和 `AGENTS.md` 是同类物，但作用域不同：**

| | 回答什么问题 | 位置 |
|---|---|---|
| `AGENTS.md` | Agent 怎么操作**这个库** | 根目录 |
| `User.md` | Agent 面对的**是谁** | **根目录（新增）** |

**融合方案**：把 `User.md` 移到新库根目录，与 `AGENTS.md` 并列。

**理由**：
- 作用域是全局的 —— 不管在哪个目录干活，Agent 都该知道你是谁
- 它不该藏在某个子目录里（现在藏在 `00-灵感库/`，容易被当成一条"灵感"忽略掉）
- 类比：这就是 Claude Code 的 `CLAUDE.md` 模式，个人档案放根目录

**建议**：内容按模板填实（现在还是空模板）。模板里那 5 组字段（基础信息 / 目标 / 约束 / 卡点 / 对顾问的要求）质量很高，**建议一个字不改直接沿用**。

---

### 4.2 缺口二：「现在用 / 未来用」分流闸门

**这是视频里最可操作的一条，而你的新库正好缺。**

**融合方案**：把它写成 `07-原子库/` 的**入口规则**。

理由：原子库现在是空的，只有一句"过了门禁四问、被挖矿压缩过的单点判断"。视频给了更实用的判据 —— **不问"这条判断对不对"，先问"什么时候能用"**。

```
新输入进来
   │
   ├─ 现在能用 ─→ 立刻列 1-2-3 行动项 → 照做（不落盘，或进 01-Projects）
   │
   └─ 未来能用 ─→ 铸成原子卡 → 07-原子库/
                     └─ 标注「触发条件」：什么情况下该取出来用
```

**⚠️ 但要给这条加一个新库才有的约束**：视频没说的是 —— "未来能用"的东西如果不写**触发条件**，它就退化成了收藏。所以原子库的卡必须有「绿灯（适用场景）」。这正好是「知识卡片」Skill 四铁律里已有的东西 —— **视频的判据和你的 Skill 天然咬合。**

---

### 4.3 张力点：视频说"不要收藏"，而你有 `Clippings/`

> 原话："是不是点收藏，不允许给我点收藏。你们那个收藏有个屁用啊，点完了以后就心里安慰而已。"

**你的新库有 `Clippings/`（网页剪藏），旧库有 190 篇剪藏 —— 这是个真实的矛盾。**

**我的判断：视频反对的是"收藏即完成"的心理安慰，不是反对保存原文。** 原文作为原料有价值（可引用、可回溯、可重读），问题在于**收藏之后就不看了**。

**融合方案**：给 `Clippings/` 加一条**强制出口规则**：

> 剪藏进来后 30 天内，必须被以下任一动作处理，否则删除：
> - 被某张原子卡引用（→ `07-原子库/`）
> - 被某篇 Wiki 引用（→ `06-Wiki/`）
> - 变成一条灵感（→ `00-灵感库/`）
>
> 判定标准：**没人引用它，它就不该占位置。**

这条规则让剪藏从"仓库"变成"传送带" —— 与视频的立场一致，也不损失原料价值。

## 5. 专章：复盘要不要占一个目录？

### 5.1 冲突事实

- 视频第四步：**"每天复盘"**，这是四步里唯一制造复利的一步
- 而在本次会话中，你刚刚决定：**`06-Journal` 改成 `06-Wiki`，不要日志库了**

**这两件事直接冲突。** 必须解决，否则视频的方法落不了地。

### 5.2 我的判断：复盘是**动作**，不是**目录**

理由：日志目录的通病是**长成流水账** —— 写了但没人回头读，等于没写。你旧库就是证据：

> 旧库 `500 Journal` 只有 **7 篇 Daily**，停在 2026-08-16，Weekly / Monthly / Quarterly **全空**。
> 建了日志体系，跑了 3 个月，然后死掉了。

**所以恢复一个 `07-日志` 是重蹈覆辙。**

### 5.3 更好的方案：复盘产物按性质归位

复盘一定会产出三种东西，它们本来就各有归属：

| 复盘产出的东西 | 去哪 | 为什么 |
|---|---|---|
| 一条可复用的判断/教训 | `07-原子库/` | 它就是一张原子卡 |
| 一个系统性认识 | `06-Wiki/` | 需要成篇展开 |
| 一个新冒出来的问题 | `00-灵感库/` | 它让你不舒服了 |

**这样做的三个好处**：
1. **不新增目录** —— 13 个目录的契约不变
2. **复盘产物直接进入流通** —— 而不是沉在日志里
3. **强制你判断产物性质** —— 比"随手写两句"质量高

### 5.4 唯一需要新增的：一条触发规则

复盘需要一个**发生的时机**。建议写进 `AGENTS.md` 的第四节（三条铁律）：

> **铁律四 · 用完必复盘** —— 任何知识用完之后，必须过一遍：
> "我是这么用的，结果是这样的，下次怎么改？"
> 复盘产物按性质归位：**判断 → `07-原子库/`；体系 → `06-Wiki/`；新问题 → `00-灵感库/`。**
> 复盘不落空 —— **没有产物的复盘不算复盘。**

**这条规则把视频的第四步接进了三环的回灌回路** —— 原本"反馈闭环：认知升级"只是个概念，现在有了具体的执行动作。
