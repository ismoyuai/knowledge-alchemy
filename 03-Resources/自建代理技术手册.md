# 自建代理技术手册（AI 落地专用）

> **适用场景**：国内常驻 + 需要稳定使用国外 AI（Gemini / OpenAI / Claude）
> **预算锚点**：¥200–300 / 年
> **依据**：NodeSeek 社区实测帖与半年总结（出处见文末），非通用教程改抄
> **原则**：只写能直接执行的东西。不解释原理，原理写在注释里。

---

## 0. 先决策：你到底要不要做这件事

**门槛（NS 半年总结原话）**：

> 自建大多数情况是稳定的，和机场在稳定性上个人没有感觉出差别。

| 你的现状 | 结论 |
|---|---|
| Gemini / OpenAI 在现有机场上**没出过**降智、没被反复人机验证、没封号 | **不要做。** 省下 200 块，现有机场继续用 |
| 出过上述任意一种 | 做。自建唯一的价值 = 给 AI 一个**独享 IP** |

### 0.1 决定成本的核心事实

这条直接决定你花 200 还是花 1200：

> 纯收一台美西机器当落地。**只要 IP 够干净**……**完全无视直连网络**：直连中国大陆的延迟/丢包都无所谓。只要能跑 3x-ui 就行，**对 CPU、内存、硬盘、流量没有任何要求（1核 256M 也可）**。
> —— NS `post-683843`，一个和你需求逐字重合的人

**推论：AI 落地机 ≠ 线路机。**
AI 是文本请求，不吃带宽、不吃延迟，只吃「IP 干净 + 没人共用」。所以那些月付十几刀的三网优化机对你**是浪费**，¥200–300/年 绰绰有余。

### 0.2 分工表（记住这张表，后面所有配置都围着它转）

| 流量类型 | 走哪 | 原因 |
|---|---|---|
| **AI**（Gemini / OpenAI / Claude / 联网工具） | **自建美西，固定节点** | 需要独享 IP |
| 视频 / 大流量 / 其他被墙站 | **现有机场** | 自建那点带宽扛不住 |
| 国内服务、商汤、DeepSeek、局域网 | **直连** | 绕出去反而慢 |

## 1. 选机与采购

### 1.1 硬指标（只有三条）

1. **独享** —— NS 原话：「一定要独享，无论是机房还是家宽，你只要分享了，**超过一定数量的同 IP 连接，大概率就会降智**」
2. **IP 干净** —— 见 §1.3，买完立刻验
3. **能跑 3x-ui** —— 1核 / 512M / Debian 12 起

**你不需要的**（别为这些加钱）：

- ❌ 家宽级 IP 纯净度 —— NS 原话：「**AI 知道你是用的 VPN，不需要家宽那种纯净度**」。要的是「没人跟你共用」，不是「像家宽」
- ❌ 大带宽、大流量 —— AI 一个月跑不掉 100G
- ❌ 三网优化回程 —— 见 §0.1

**禁止事项**：

- ❌ **拼车** —— NS 原话：「你是不知道同车的人会干什么，除非认识，否则**极度不建议**」
- ❌ **用学生 / 教师 / 拼车账号跑 AI** —— NS 原话：用常规付费账号
- ❌ **追热门线路**（DMIT、搬瓦工这类）—— 不是它们不好，是「这个月人少就好，下个月人多又差了」
- ❌ **自动切换节点** —— 见 §10 铁律

## 2. 服务端部署

### 2.1 系统初始化

- 后台重装为**全新的 Debian 12**（干净系统，别用商家预装镜像）
- 确认商家**安全组 / 防火墙**已放行 `443` 和 SSH 端口 —— 这步忘了后面全白干

### 2.2 开 BBR

```bash
echo "net.core.default_qdisc=fq" >> /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" >> /etc/sysctl.conf
sysctl -p
sysctl net.ipv4.tcp_congestion_control     # 必须输出 bbr
```

### 2.3 装 3x-ui

> ⚠️ **注意**：NS `post-593805` 里推荐的一键脚本 `Chil30/vless-all-in-one` **已经 404 了**（我实测过）。用下面这个。

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

装完：

```bash
x-ui            # 进管理菜单：重置用户名密码、改面板端口、改访问路径
```

**面板安全（必做）**：

- 面板端口**改掉默认值**，访问路径改成一个随机长串
- 面板**不要暴露公网**：安全组里只放行你自己的固定 IP，或者只监听 `127.0.0.1` 然后走 SSH 隧道访问
- 防火墙最终只留两个口：`443`（节点）和 SSH

### 2.4 VLESS + Reality 入站（逐字段配置）

**新增入站**，按下表填。这是实测可用的参数集：

| 分组 | 字段 | 值 |
|---|---|---|
| **基础** | 启用 | ✅ |
| | 备注 | `vless-reality-vision` |
| | 协议 | `vless` |
| | 监听 IP | 留空 |
| | **端口** | **`443`** |
| **协议** | 解密 / 加密 | `none` |
| | 客户端 Flow | **`xtls-rprx-vision`** |
| **传输** | 传输方式 | **`RAW`**（旧版显示 TCP） |
| | Proxy Protocol / HTTP 混淆 / External Proxy / Sockopt | 全**关闭** |
| **安全** | 安全类型 | **`Reality`** |
| | uTLS | **`chrome`** |
| | **Target** | **`www.amd.com:443`** |
| | **SNI** | **`www.amd.com`**（与 Target 一致） |
| | **Short IDs** | **只留一个**（便于排查） |
| | SpiderX | `/` |
| | Public / Private Key | 点 **Get New Cert** 自动生成 |
| | Max Time Diff | `0` |
| | Min / Max Client Ver | 留空 |
| **Sniffing** | 启用 | ✅ |
| | 勾选 | `HTTP` `TLS` `QUIC` |
| | FAKEDNS | ❌ 不勾（新手先关） |

> **Target / SNI 怎么选**：挑一个大站 —— 国内可正常访问、支持 TLS 1.3、HTTP/2。社区常用 `www.amd.com`、`www.microsoft.com`。**别用 Cloudflare 后面的站**。

**命令行生成密钥**（面板也能点，二选一）：

```bash
xray x25519                      # 输出 Private key / Public key
xray uuid                        # 生成 UUID
openssl rand -hex 8              # 生成 Short ID
```

### 2.5 从面板导出客户端链接

面板里点客户端的**二维码 / 复制链接**，得到一条 `vless://`：

```

&sni=www.amd.com&fp=chrome&pbk=<公钥>&sid=<ShortID>#美西落地
```

## 3. 客户端接入

### 3.1 客户端选型

> 依据：NS `post-568733` 的全平台横评

| 客户端 | 什么时候用它 | 注意 |
|---|---|---|
| **V2rayN** | **自建 / 单节点**首选。协议覆盖第一，新协议跟进最快 | 分流弱、UI 复古 |
| **Clash Verge Rev** | **要分流就用它**（你的场景必须分流） | ≥2.3.0 版本 bug 渐多 |
| Sparkle / GUI.for.SingBox | sing-box 系，随缘更新 | — |
| ⚠️ **Clash Party** | **别用** —— 已易主，「继任开发者是某机场的利益相关者」 | — |
| 🔴 已死 | Clash for Windows · Netch · Nekoray · Hiddify | 别装 |

**结论**：装 **Clash Verge Rev**（要分流）+ **V2rayN**（调试时用，导入 `vless://` 最快）。

### 3.2 推荐架构：Sub-Store 把自建和机场合成一条订阅

这是 NS `post-568733` 里给出的方案，正好解决你的场景 —— **让客户端只订阅一条 URL，同时含自建节点和你的机场订阅**：

```
Sub-Store（跑在 VPS 或 NAS 的 Docker）
  ├─ 单条链接 A = 你的自建 vless:// 节点
  ├─ 单条链接 B = 机场订阅链接
  ├─ 组合订阅 C = A + B
  └─ Mihomo 配置 → 输出一条 Clash 配置链接
                      ↓
        家里 + 公司的 Clash Verge Rev 都只订阅这一条
```

好处：以后换节点、换机场，只在 Sub-Store 改一次，两台设备自动同步。

### 3.3 分流规则（已按你的真实后端写好）

**你现有环境里的后端**（我从 `~/.pi/agent/models.json` 与 `web-search.json` 读出，未打印任何密钥）：

| 后端 | 域名 | 归属 | 该走哪 |
|---|---|---|---|
| 商汤（国产聚合网关） | `token.sensenova.cn` | 国内 | **DIRECT** |
| DeepSeek 原厂 | `api.deepseek.com` | 国内 | **DIRECT** |
| vllm 本地自建 | `192.168.5.8:8888` | 局域网 | **DIRECT** |
| xKiro | `api.xkiro.com` | ⚠️ 待确认 | 若为海外中转 → 自建 |
| Gemini | `generativelanguage.googleapis.com` `aistudio.google.com` `gemini.google.com` | 海外 | **自建美西** |
| OpenAI | `api.openai.com` `chatgpt.com` | 海外 | **自建美西** |
| Claude | `api.anthropic.com` `claude.ai` | 海外 | **自建美西** |
| Tavily（搜索） | `api.tavily.com` | 海外 | **自建美西** |
| Jina（搜索 / 抓取） | `api.jina.ai` `r.jina.ai` `s.jina.ai` | 海外 | **自建美西** |
| 其他被墙 | YouTube / GitHub / Google 搜索 | 海外 | **机场** |

**Clash Verge Rev 配置片段**（合并进你的 config.yaml）：

```yaml
proxies:
  - name: "美西落地"
    type: vless
    server: <你的IP>
    port: 443
    uuid: <你的UUID>
    network: tcp
    tls: true
    udp: true
    flow: xtls-rprx-vision
    servername: www.amd.com
    client-fingerprint: chrome
    reality-opts:
      public-key: <你的公钥>
      short-id: <你的ShortID>
  # 「红杏云」等机场节点由订阅提供，不用手写

proxy-groups:
  - name: "AI"
    type: select
    proxies: ["美西落地"]        # 固定，不放其他选项 = 物理上防止乱跳
  - name: "默认"
    type: select
    proxies: ["红杏云", "美西落地", "DIRECT"]

rules:
  # ① 内网 & 国内 AI 后端 → 直连
  - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
  - IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
  - IP-CIDR,192.168.5.8/32,DIRECT,no-resolve
  - DOMAIN-SUFFIX,sensenova.cn,DIRECT
  - DOMAIN-SUFFIX,deepseek.com,DIRECT

  # ② 海外 AI + 联网工具 → 自建美西（固定）
  - DOMAIN-SUFFIX,generativelanguage.googleapis.com,AI
  - DOMAIN-SUFFIX,aistudio.google.com,AI
  - DOMAIN-SUFFIX,gemini.google.com,AI
  - DOMAIN-SUFFIX,openai.com,AI
  - DOMAIN-SUFFIX,chatgpt.com,AI
  - DOMAIN-SUFFIX,anthropic.com,AI
  - DOMAIN-SUFFIX,claude.ai,AI
  - DOMAIN-SUFFIX,tavily.com,AI
  - DOMAIN-SUFFIX,jina.ai,AI

  # ③ 兜底
  - GEOIP,CN,DIRECT
  - MATCH,默认
```

> ⚠️ **规则顺序不能乱**：具体域名必须在 `GEOIP,CN` 和 `MATCH` 之前，否则会被兜底规则吃掉。

### 3.4 端口对齐（这步忘了就会以为代理没生效）

你的 `~/.pi/agent/web-search.json` 里 `proxy` 写的是 `http://127.0.0.1:7890`。

所以：**把 Clash Verge Rev 的混合端口（mixed-port）设成 `7890`**，这样两台机器的 pi 配置一行都不用改。

（如果不想改客户端端口，就反过来改 `web-search.json` 里的 `proxy` 值 —— 但**改完必须重启 pi**，该配置有进程级缓存，只在启动时读一次。）

## 4. 家里：绿联 NAS 当常驻网关

**这是你现有条件里最值钱的一点** —— 台式机会关机，NAS 不会。

```
绿联 NAS（Docker 跑 mihomo，7×24 常开）
   ├─ 开启 allow-lan
   ├─ 暴露 mixed-port: 7890
   └─ 家里其他设备把「HTTP 代理」指向 NAS_IP:7890
        → 手机 / iPad / 电视 / 台式机全部覆盖，台式机不用开着
```

**要点**：

- 在 UGOS Pro 的 Docker 里跑一个 mihomo 容器（配置就是 §3.3 那份，加一行 `allow-lan: true`）
- 容器端口映射 `7890:7890`，网络模式用 `host` 最省事
- 家里设备：Wi-Fi 设置 → HTTP 代理 → 手动 → `NAS_IP` : `7890`
- ⚠️ 具体菜单以你 NAS 的实际界面为准
- 进阶（可选，别一上来就做）：开 TUN 透明代理，把 NAS 当网关，设备连 DHCP 下发的网关就自动走分流

## 8. 运维

### 8.1 IP 被墙了怎么判断、怎么修

**判断顺序**（从便宜到贵）：

| 现象 | 结论 | 处理 |
|---|---|---|
| 节点全超时，但 SSH 能连上 | **只是端口被封** | 面板换端口（443 → 其他常用端口），成本 0 |
| 换端口也不行 | 可能是 SNI/Target 被识别 | 换一个 Target/SNI 大站，成本 0 |
| SSH 也连不上、ping 不通 | **整个 IP 被墙** | 找商家换 IP（多数收费，事先买前问清政策），或直接换商家 |

**换了之后必须做**：更新 Sub-Store 里的节点 → 两台设备自动同步。

### 8.2 加落地机（进阶，暂不需要）

当 AI 侧再次出问题时，引入「入口 + 落地」分离：

```
你的设备 → 入口机（线路好） → 落地机（IP 干净） → AI
```

sing-box 用出站链实现，或者简单点：入口机转发到落地机端口。

## 9. 排错速查

| 症状 | 最可能的原因 | 先查什么 |
|---|---|---|
| 客户端显示连接成功但打不开网页 | 分流规则顺序错，被 `MATCH` 兜底吃掉了 | §3.3 规则顺序 |
| pi 的搜索全部失败 | 没重启 pi / proxy 端口与客户端不一致 | §3.4，先 `curl -x` 手测 |
| 只有 Gemini 不通，其他正常 | AI 规则没生效，或该机器 IP 被 Google 标记 | §1.3 重验 IP 干净度 |
| 延迟测试一直 timeout | 商家安全组没放行 443 | §2.1 |
| Reality 配好了但连不上 | Target / SNI / ShortID / 公钥 四者之一与客户端不一致 | §2.4 逐字段核对 |
| 用几天后开始频繁人机验证 | **有别人在共用你的 IP**，或你在自动切换节点 | §10 铁律 1、2 |
| 家里其他设备连不上代理 | NAS 的 `allow-lan` 没开 / 端口没映射 | §4 |

## 10. 铁律（NS 上的血泪，违反一条白花钱）

1. **固定节点，不要乱跳 IP**
   > AI 应用固定使用这一个节点连接。**不要乱跳 IP**。 —— `post-593805`

2. **不拼车，不共享**
   > 超过一定数量的同 IP 连接，大概率就会降智……除非认识，否则极度不建议。 —— `post-593805`

3. **不用学生 / 教师 / 拼车账号跑 AI**
   > AI 应用使用**常规付费**账号。 —— `post-593805`

4. **先月付，再年付**
   > 推荐先月付测试没问题再考虑年付。 —— `post-763360`

5. **别成天泡论坛**
   > 买到了 VPS 以后**就别看网站了**……为了追求一点细节提升，成天泡在上面挺浪费时间的。不要在意活动价格，一般也就几十块钱差价。 —— `post-593805`
